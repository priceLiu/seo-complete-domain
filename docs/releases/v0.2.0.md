# v0.2.0 发布说明

**发布日期**：2026-05-19  
**标签**：`v0.2.0`

## 1. 需求

- 接入 **Bing Webmaster JSON API**：在「收录与索引」页展示账号下站点、与 `NEXT_PUBLIC_SITE_URL` 同域匹配及 **排名/流量**（展示、点击）时间序列，并用 ECharts 折线图呈现。  
- 为 **`POST /api/audit/run`** 增加可选 **服务端密钥**（`AUDIT_RUN_SECRET`），避免公网暴露时任意触发抓取。  
- 审计页根据 `GET /api/audit/config` 自动提示是否需要填写密钥。

## 4. 完成情况

- Bing：`https://ssl.bing.com/webmaster/api.svc/json/GetUserSites`、`GetRankAndTrafficStats`（`siteUrl` 使用 Webmaster 中登记的 URL）。  
- 密钥：`BING_WEBMASTER_API_KEY` 仅服务端；`AUDIT_RUN_SECRET` 使用 SHA-256 `timingSafeEqual` 比对（传入的明文与配置值哈希比较）。  
- 未配置 `AUDIT_RUN_SECRET` 时行为与 v0.1.0 一致，便于本地开发。

## 5. 遗留问题

- Bing：**收录量 / 抓取配额** 等更多接口可按需在后续版本扩展；当前以流量序列为主。  
- **百度**：仍无开放 API 自动索引数据，策略见收录页说明。  
- **审计密钥**：前端为人工输入，生产环境更推荐仅服务端 Cron 带密钥调用 API，避免浏览器侧暴露习惯。  
- **依赖审计**：`npm audit` 仍有上游告警，未在本版强制 `audit fix --force`。

## 6. 升级与配置摘要

```bash
# .env.local 示例
NEXT_PUBLIC_SITE_URL=https://你的域名
BING_WEBMASTER_API_KEY=你的_Bing_API_密钥
# 生产建议开启：
# AUDIT_RUN_SECRET=随机长字符串
```

安装依赖并构建：`npm install && npm run build`。
